# atlantis-config-gen

[![ci](https://github.com/moveeeax/atlantis-config-gen/actions/workflows/ci.yml/badge.svg)](https://github.com/moveeeax/atlantis-config-gen/actions/workflows/ci.yml)
[![Go](https://img.shields.io/badge/go-1.26%20%7C%201.27-00ADD8?logo=go&logoColor=white)](go.mod)
[![License: MIT](https://img.shields.io/badge/license-MIT-green.svg)](LICENSE)

Stop hand-writing `atlantis.yaml`. `atlantis-config-gen` derives it from your
repository's Terraform layout: it finds root modules, follows the local modules
they use (transitively), and emits Atlantis projects whose `autoplan` triggers
cover every file that can change a plan — including a shared module three levels
down.

## What it does

- **Finds root modules** — a directory is a root if it configures a `backend`
  (or `cloud`) block or declares a `provider`. Shared modules under `modules/`
  are not roots and never get their own project.
- **Resolves transitive module deps** — if `services/api` uses `modules/app`,
  which uses `modules/vpc`, which uses `modules/subnet`, all three land in that
  project's `when_modified` list, each path relative to the project dir.
- **Detects environments from tfvars** — `prod.tfvars` and `staging.tfvars`
  become one project per environment with a matching `workspace`.
  `terraform.tfvars` and `*.auto.tfvars` are auto-loaded defaults, so they don't
  spawn environments.
- **Pins the Terraform/OpenTofu version** — an exact `required_version`
  (`"1.9.8"` or `"= 1.9.8"`) becomes the project's `terraform_version`. Without
  one, the nearest `.terraform-version` (or `.opentofu-version` with
  `--tf-distribution opentofu`) is used, searched from the project dir up to
  the repo root like tfenv/tofuenv do. Ranges such as `">= 1.5.0"` and
  non-exact file values such as `latest` pin nothing, so Atlantis keeps its own
  default. `--tf-distribution` also writes `terraform_distribution`.
- **Diff mode** — `--diff` prints a unified diff against the existing file and
  exits non-zero when they differ, so CI can fail on drift without writing.
- **Idempotent** — projects and trigger lists are fully sorted; re-running on an
  unchanged tree produces byte-identical output.
- **Configurable naming** — `--name-template` (Go template over `.Dir`, `.Base`,
  `.Path`, `.Env`) and `--workflow` to attach a named Atlantis workflow.

## How it works

Each `.tf` file is parsed with HashiCorp's HCL library. For every directory the
tool records whether it has a backend/provider block and which local `module`
sources it calls. Roots are the directories with a backend or provider; their
dependency closure is walked breadth-first over module calls, so a change deep
in the module tree still replans the root that pulls it in. Trigger paths are
emitted relative to the project directory, exactly how Atlantis evaluates
`when_modified`.

## Install

Requires Go 1.26 or newer (CI tests 1.26 and 1.27).

```shell
go install github.com/moveeeax/atlantis-config-gen@latest
```

Or build from source:

```shell
git clone https://github.com/moveeeax/atlantis-config-gen
cd atlantis-config-gen
go build -o atlantis-config-gen .
```

## Usage

```shell
atlantis-config-gen --root . --out atlantis.yaml
```

Against the bundled example repo:

```console
$ atlantis-config-gen --root examples/sample --out -
# Generated by atlantis-config-gen. Re-run to update; do not edit by hand.
version: 3
projects:
  - name: api-production
    dir: services/api
    workspace: production
    autoplan:
      when_modified:
        - '*.hcl'
        - '*.tf'
        - '*.tfvars'
        - ../../modules/app/*.tf
        - ../../modules/subnet/*.tf
        - ../../modules/vpc/*.tf
      enabled: true
    apply_requirements:
      - approved
  ...
```

Check for drift in CI (exits 2 if the committed file is stale):

```shell
atlantis-config-gen --root . --out atlantis.yaml --diff
```

### Flags

| Flag | Default | Description |
| --- | --- | --- |
| `--root` | `.` | Repository root to scan. |
| `--out` | `atlantis.yaml` | Output file (`-` for stdout). |
| `--diff` | `false` | Print a diff vs. the existing file; exit 2 if it differs. |
| `--workflow` | `` | Attach this Atlantis workflow to every project. |
| `--name-template` | `{{.Base}}{{if .Env}}-{{.Env}}{{end}}` | Go template for project names. |
| `--automerge` | `false` | Set `automerge: true`. |
| `--parallel` | `false` | Set `parallel_plan` and `parallel_apply`. |
| `--tf-distribution` | `` | `terraform` or `opentofu`: set `terraform_distribution` on every project and pick the matching version file. |

## Development

```shell
go test ./...   # unit tests + fixture-driven discovery tests
go vet ./...
```

The `examples/sample` tree doubles as a test fixture and a live demo; its
generated `atlantis.yaml` is committed so CI can assert the tool stays
idempotent.
